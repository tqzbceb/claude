# dcwatch · 轻量 Discord 监听 + 模型工作台

> **你是被叫来接手这个项目的 AI？别从这份 README 开始。**
> 按顺序读根目录的 `AGENTS.md`（项目记忆、用户是谁、十一条硬规矩、排查固定顺序）→
> `HANDOFF.md`（上一轮做到哪、下一步做什么）→ `CLAUDE.md`（用户定的工作协议）。
> 回归套件在 `tests/`，`cd tests && ./runall.sh e2e.py e2e_ai.py`。
> **这三份文件 + `tests/` 就是全部交接内容，不需要任何聊天记录**（干净 clone 已实测能跑回归）。
> 这份 README 是写给使用者的说明书，你要改代码的话它只用来查「某个功能对用户的承诺是什么」。
> 人类用户想知道怎么换账号接手，见最后一节「十一、换个账号 / 换个 AI 接手」。

一个进程、一个依赖（aiohttp）、一个 SQLite 文件、一个网页界面。常驻内存约 40–60 MB。
不用 Electron、不用 Node、不用 discord.py。

```
pip install aiohttp
python server.py            # 打开 http://127.0.0.1:8777
```

文件：`server.py`（后端）· `ui.html`（界面）· `extension/`（Chrome 扩展，免 Token 方案）·
`build.bat` + `dcwatch.spec`（打包成 exe）· `dcwatch.db`（自动生成，配置+消息都在里面）

**Windows 上最省事**：双击 `启动.bat`（自动装依赖 + 启动 + 打开界面）。
想要单个 exe、以后不依赖 Python，双击 `build.bat`，见第八节。

## 零、从云端拿到你的电脑上

程序是在 cloud.browser-use.com 的工作区里生成的，只有 `outputs/` 里的文件你能下载。

1. 在聊天界面右侧的**文件面板**里找 `dcwatch.zip`（整包，含扩展），点下载；
   单个文件也可以分别下 `dcwatch/server.py`、`dcwatch/ui.html`、`dcwatch/extension/*`。
2. 解压到任意文件夹，比如 `D:\dcwatch` 或 `~/dcwatch`。
3. 装 Python 3.10+（安装时务必勾上 **Add python.exe to PATH**）。
4. **Windows 最省事：双击 `启动.bat`。** 它自己检查 Python、缺依赖就装（默认源装不上会自动换国内源）、
   **清掉上次没退干净、还占着 8777 的僵尸进程**、然后启动并打开界面。以后每次开都双击它。

   端口这块你不用管了：
   - 上次的进程赖着不走 → 自动结束它再启动（只对 `python.exe` / `dcwatch.exe` 动手）
   - dcwatch 本来就在跑 → 不开第二个，直接把界面打开给你
   - 端口被**别的程序**占着 → 明确告诉你是哪个程序，不擅自去杀
   - 想换端口：`启动.bat 8778`（扩展弹窗里的端口也要改成一样的）

   **想彻底停掉：双击 `停止.bat`**（也可以带端口：`停止.bat 8778`）。它先请程序自己退出，
   退不干净就强制结束，最后确认端口真的空出来了。关掉黑窗口也算停。

   自己敲命令也行，注意**两条命令分两行敲**——Win11 默认终端是 PowerShell，`&&` 在里面会报错：

```bash
cd dcwatch
python -m pip install aiohttp
python server.py --open     # 不加 --open 不会自动开浏览器
```

   在文件夹里开命令行的快捷办法：把资源管理器**地址栏**的路径删掉，输入 `cmd` 回车，
   这样目录就是当前文件夹，不会出现 `can't open file 'server.py'`。

5. 浏览器打开 http://127.0.0.1:8777 。全部数据都在你本机，云端不留任何东西。
   以后我改了代码，你重新下 zip 覆盖 `server.py` / `ui.html` 就行，`dcwatch.db` 不要删（配置和历史在里面）。

## 〇点五、你没有 Bot 权限时，三条路怎么选

|  | 路线 A · 浏览器旁听 | 路线 B · Bot Token | 路线 C · 个人账号 Token |
|---|---|---|---|
| 需要什么 | 只要你自己的 Discord 账号 | 能把 bot 拉进服务器（需该服务器「管理服务器」权限） | 你的账号 token |
| 合规 | 只读你自己已登录的页面，不碰 Discord API | 官方支持 | **违反 ToS，可能永久封号** |
| 要开浏览器吗 | 要，频道得留在标签页里 | 不用，后台常驻 | 不用 |
| 能收私密/未开频道吗 | 你能看见的就能收 | 只能收 bot 有权限的频道 | 你能看见的全都收 |
| 能自动回复吗 | 不能，只能收 | 能 | 技术上能，但风险最大，本程序默认不发 |
| 延迟 | 1–2 秒 | <1 秒 | <1 秒 |

顺便纠正一点：**创建 bot 本身任何人都能做、免费、不用审核**（developers portal 点几下就有 token）。
卡住你的不是 token，是「把 bot 邀请进那个服务器」需要服务器管理权限。
所以如果那个服务器是你自己的或者你是管理员 → 直接走路线 B，最省心；
如果是别人的服务器你只是普通成员 → 走路线 A（下面第二节-1）；实在要后台无人值守才考虑 C，风险自负。

### 路线 A：浏览器旁听（推荐给普通账号）

原理：Chrome 扩展在你已经登录的 discord.com 页面里，只读地盯着聊天区 DOM，
一有新消息就把「谁、在哪个频道/子区、说了什么」POST 给你本机的 dcwatch（`POST /api/ingest`），
之后的规则匹配、AI 判分、通知、AI 工作台全都一样跑。它不读你的 token，不向 Discord 发任何请求。

扩展一共两个脚本：`content.js` 只在 Discord 页面里读 DOM，`background.js` 负责把解析结果发给本机
（Chrome 会拦「网页 → 本地地址」的请求，所以这一步必须由后台脚本做，不能让页面脚本自己发）。

装法（30 秒）：
1. `python server.py` 先跑起来；
2. Chrome 地址栏进 `chrome://extensions` → 右上角打开「开发者模式」→「加载已解压的扩展程序」→ 选 `dcwatch/extension` 文件夹；
   （也可以在界面「设置 → ↓ 下载浏览器扩展」拿到 zip，**先解压**再选解压出来的文件夹——Chrome 不能直接装 zip）
3. 打开 `https://discord.com/channels/...`，登录你自己的账号，切到要盯的频道（子区就把子区面板点开）；
4. **在 Discord 标签页按 F5 刷新一次。** 内容脚本只在页面加载时注入，装扩展前就开着的标签页没有它
   ——这是「左下角灯不亮」最常见的原因。
5. 回 dcwatch 界面「设置 → 接入方式 = 浏览器旁听」，左下角「浏览器旁听」变绿点＝扩展在线。

**装好之后你会看到什么**：Discord 页面**右下角出现一个小药丸** `● dcwatch 正在旁听`。
绿点＝通了，红/橙＝有问题。点它展开小面板：本机程序在不在、这一页在盯哪个频道、已上报几条、
服务端累计几条，以及一句「该怎么修」。面板里还能发一条测试消息、直接打开 dcwatch 界面。
不想看它就点「不再显示」（想找回来：在页面控制台执行 `__dcwatch.show()`）。

**灯不亮怎么查（第二个入口）**：点浏览器工具栏上的 dcwatch 图标。图标角标就是状态——`ON` 绿＝正常旁听中，
`?` 橙＝dcwatch 在跑但没有标签页在旁听（去刷新 Discord 页面），`!` 红＝连不上 dcwatch（没启动或端口不对）。
点开图标有四项自检（程序 / 标签页 / 投递 / 服务端看到），每种情况都写了该怎么修；
还能改端口（不用再改代码）、发一条测试消息验证「网页 → 扩展 → dcwatch → 规则 → 通知」整条链路。
工具栏上看不到图标就点那个拼图图标，把 dcwatch 固定出来。

**更新扩展（覆盖了新文件之后）必须做两步，少一步等于完全没改**：
1. `chrome://extensions` → 找到 dcwatch → 点卡片上的**刷新箭头 ⟳**；
2. 回到 Discord 页面**按 F5**。

卡片上的版本号是你唯一的自查凭据，当前应该是 **v1.8.0**（扩展和程序是两个东西，
号不必相同：程序现在是 v1.9.0，而 **v1.9.0 没有改扩展**，所以扩展停在 v1.8.0，
你不用为这一版重装扩展）。
版本对不上时，扩展弹窗顶部和 dcwatch 界面顶部都会直接提示你去刷新。

**用哪个浏览器**：推荐 Chrome 或 Edge（同内核）。「加载已解压的扩展程序」装上去是持久的，重启浏览器还在。

不支持火狐：标准版火狐不允许长期安装未签名扩展，只能每次开浏览器手动临时载入一遍，
对一个常驻收信的工具来说不实用，所以这里只做 Chromium 系（Chrome / Edge / Brave 等）。

**多个号 / 多个浏览器一起盯**：装了扩展的每个浏览器都是一个独立的「桥」，
dcwatch 会在界面左下角把它们分别列出来（哪个账号、哪个浏览器、在盯哪个频道、多久前有心跳、扩展版本）。
- 想同时盯两个 Discord 账号：用两个浏览器（或 Chrome 的两个用户配置），各自登一个号、各自装扩展。
  两边收到的消息会合到同一个收信箱，每条消息记着是哪个号收到的。
- 规则可以只盯某个号：规则编辑器「听哪里」里会多出一个「只听这些账号」（检测到 2 个以上账号时才出现），
  不勾＝所有号都听。
- 两个浏览器同时开着同一个频道时，同一条消息会被报两次 —— dcwatch 按消息 ID 去重，
  只入库一条、规则只跑一次、通知只发一次，不会重复扣 AI 调用。

限制说清楚：
- **标签页要留着**。Discord 网页版只渲染当前打开的频道，没打开的频道扩展看不见（这是这条路的根本限制）。
  想同时盯多个频道 → 开多个 Discord 标签页，每个停在一个频道。
- 只有文字会转发（纯图片/贴纸没有文字就跳过）；刚打开或刚切频道的历史消息不算新消息，不会灌进来。
- 只能收不能发：`AI 自动回复` 这类动作在这条路下会报「发消息需要 Bot Token」，改用 `AI 判重要度` / 摘要 / Webhook。
- 端口不是默认 8777 时**不用改代码**：点工具栏的 dcwatch 图标，在弹窗底部把端口改成一样的，保存即可。

### 路线 C：个人账号 Token（不推荐）

设置页选「个人账号 Token」会弹二次确认。程序在这个模式下只连 Gateway 收消息、不主动发。
即便如此，这仍然是 Discord 明令禁止的 selfbot 行为，被判定就是封号，且申诉基本无用。
写在这里是因为它技术上确实可行、你有权知道，但请优先 A 或 B。

## 一、监听到底是怎么监听的（不是轮询）

Discord 有一条长连接叫 **Gateway**（WebSocket）。dcwatch 连上去之后，
你的 bot 能看见的每一条新消息，Discord 会**主动推**过来一个 `MESSAGE_CREATE` 事件，里面有：

| 字段 | 含义 | 界面里对应 |
|---|---|---|
| `guild_id` | 服务器 ID | 服务器 ID |
| `channel_id` | 频道 ID；**消息发在子区时，这里是子区的 ID** | 频道 ID / 子区 ID |
| `author.id` | 发言人 ID | 用户 ID |
| `content` | 正文 | 关键词 / 正则 |
| `mentions[]` | 被 @ 的人 | 只在 @ 我时触发 |

所以“监听某人 / 某频道 / 某子区”本质上是：**收到每条推送 → 拿上面这些字段和你的规则比对**。
延迟通常 < 1 秒，没有轮询，不消耗 API 配额。

子区（thread）在 Discord 里是一个独立频道，有自己的 ID。所以有两种写法：
- 想连子区一起听：在规则里填**父频道 ID**，勾上「同时监听这些频道下的所有子区」（用 `parent_id` 匹配）；
- 只想听一个子区：把那个子区的 ID 填进「只听某个子区」。

> 上面说的 Gateway 是**路线 B/C**（Token 直连）的工作方式。
> **路线 A（浏览器旁听）**不连 Gateway，它读的是 Discord 网页版已经渲染出来的消息，
> 字段是一样的（频道 ID、子区的 parent、作者 ID 从头像 URL 里取），所以同一套规则通用。

## 二、你需要填的东西

走浏览器旁听的话，**Token 那一栏不用填**，只需要下面第 2、3 项（ID 和模型）。

### 1. Bot Token（只有路线 B/C 需要）
1. https://discord.com/developers/applications → New Application
2. 左侧 **Bot** → Reset Token → 复制
3. 同一页往下：**Privileged Gateway Intents** → 打开 **MESSAGE CONTENT INTENT**
   （不开的话消息能收到，但 `content` 是空字符串——界面上会显示“可能未开 MESSAGE CONTENT”）
4. 左侧 **OAuth2 → URL Generator** → 勾 `bot` → 权限勾 `View Channels` + `Read Message History`
   （要让 AI 自动回复再加 `Send Messages`、`Send Messages in Threads`）→ 用生成的链接把 bot 拉进服务器
5. 界面「设置」→ 粘贴 Token → 勾「启用 Discord 监听」→ 保存并连接

> 只支持 bot token。用个人账号 token 做自听（selfbot）违反 Discord ToS，会封号，本程序不做。
> Bot 看不到它没权限的频道——想监听私密频道，需要给它开那个频道的查看权限。

### 2. 各种 ID（三种拿法）
- **从收到的消息里抄**（浏览器旁听最方便）：先随便让它收一条，收信箱点开消息，
  详情页直接显示 `author_id` / `channel_id`，或者点「按此消息新建规则」，ID 自动填好。
- **界面里挑**（需要 Token）：规则编辑器 → 频道 ID 右边「从服务器里挑 ▾」，列出服务器 → 频道 → 活跃子区，点一下就填。
- **手动复制**：Discord 设置 → 高级 → 打开 **开发者模式**，然后右键服务器/频道/子区标题/某人头像 → 复制 ID。
  也可以在收信箱点开任意一条消息，详情页直接显示该消息的 `author_id` / `channel_id`。

### 3. 模型端点
「模型接入」页：填 Base URL（要带 `/v1`）+ API Key → 点 **⇣ 拉取模型列表**（打 `GET /v1/models`）→ 选一个设为默认。
任何 OpenAI 兼容服务都行：

| 服务 | Base URL |
|---|---|
| OpenAI | `https://api.openai.com/v1` |
| DeepSeek | `https://api.deepseek.com/v1` |
| OpenRouter | `https://openrouter.ai/api/v1` |
| Ollama（本地免费） | `http://127.0.0.1:11434/v1` |
| LM Studio / vLLM | `http://127.0.0.1:1234/v1` |

地址粘错了也没关系：少了 `/v1`、多带了 `/chat/completions`、末尾多几个斜杠，程序都会自己试着修正。
**拉不到模型列表时先看错误提示**，它会告诉你是连不上、Key 不对、还是地址不对：
- 「连不上对方服务器」＝网络到不了。国内直连 `api.openai.com` 基本不通，
  去**设置页填一个代理**（比如 `http://127.0.0.1:7890`，端口跟你的代理软件对一下），
  或者换 DeepSeek / 通义 / 本机 Ollama 这类能直连的。留空＝跟随系统代理。
- 「401」＝Key 错了或没填。「404」＝地址不对，照上面表格核对。

注意：拉不到就是拉不到，界面**不会**给你一份编出来的模型列表充数
（下拉里带「（演示）」前缀的才是演示数据，只在完全没连上本机程序时才会出现）。

## 三、规则在哪设置 = 左侧「监听规则」

一条规则读起来就是一句话：**听哪里 · 听谁 · 听到什么 → 做什么**。编辑器就是这四段 + 试算：

1. **听哪里**：服务器 ID / 频道 ID（可多个，可含其子区）/ 子区 ID / 是否含私信。
   频道那几栏全留空 = 所有能收到的频道都算。但**私信是例外：默认不听**，要收私信得单独勾上「包含私信 DM」
   （不勾的话，私信来的消息试算会告诉你被 `dm-off` 挡下了）。
2. **听谁**：用户 ID（最准）/ 昵称包含 / 只在 @ 我时 / 忽略机器人。
   多个 Discord 账号在旁听时，「听哪里」里还会多出「只听这些账号」，用来给不同号配不同规则。
   浏览器旁听模式下，**没上传过头像的人拿不到用户 ID**（Discord 的默认头像链接里不带 ID），
   收信箱里这种人的 `author_id` 是空的。对付这种人用「昵称包含」。
3. **听到什么**：含任一关键词、必须同时含、正则、最短字数。全留空 = 该范围每条都算命中。
   **纯表情包 / 图片 / 贴纸**的正文会写成 `[图片]`、`[贴纸 猫猫点头]`、`:kekw:` 这样（v1.8.0 起），
   所以想连它们一起收，这一栏别填关键词，「最短字数」也要是 0。
4. **做什么**：见下一节。另有**冷却秒数**和**每小时上限**，防止刷屏把钱烧掉。
5. **试算**：填个假消息，点「试算」，立刻告出命中 / 不命中以及被哪一条挡下（`author` / `kw-any` / `regex`…）。
   不连 Discord 也能调规则。

规则之间是**并行**的：一条消息会跟所有启用的规则比对，命中几条就执行几条动作。

### 规则可以整包导出 / 导入（v1.9.0 起）

「监听规则」页顶上多了两个按钮，用来把辛苦填好的规则搬走、或者拿别人调好的一份直接用：

- **⇡ 导出规则**：所有规则存成一个 `.json` 文件下载下来，文件名带条数和版本号
  （`dcwatch-规则5条-v1.9.0-0731-1420.json`）。里面**只有规则**，没有 Token、没有 API Key、
  没有你收到的消息 —— 可以放心发给别人。命中次数是本机的账，不跟着走。
- **⇣ 导入规则**：选那个文件，**先给你看一页预览再问你要不要**：
  哪几条是新增（`＋`）、哪几条会覆盖现有的同名规则（`↻`，并逐条列出「关键词：空投 → 空投、白名单」
  这样的变化）、哪几条其实一模一样（`=`）。有问题的地方会用 ⚠ 标出来（比如文件里的动作要用大模型、
  但你还没配模型）。**点「确认导入」才会真写进去。**
  - 两种合法：**合并**（同名的覆盖，其余新增，你自己多出来的规则留着）和
    **替换全部**（本机规则变成跟文件完全一样，多出来的删掉 —— 会再问你一次）。
  - 认的是**规则名**，不是 ID：两台机器上的 id 必然不同，名字才是你看得懂的东西。
    所以想覆盖某条，就让文件里的名字跟本机那条一样。
  - 覆盖不会清掉这条规则的命中次数，重复导入同一个文件也不会造出一堆重复规则。
  - 文件选错了不会出乱码报错：不是规则包就直接告诉你「这不是 dcwatch 的规则包」。
    别人机器上的**频道 ID 会原样保留**（你这边还没收到过那个频道的消息也没关系），
    但明显不是 ID 的值会被丢掉并写在预览里。

### 三点五、不想手填？两条路：让 AI 问清楚，或者直接吩咐它改

规则可以完全不用手填。两个入口，用哪个看你说得清不清楚：

- **说不清**：用「监听规则」页顶部的**向导**，它反问你几轮再生成（下面这一节）；
- **说得清**：直接去「AI 工作台」吩咐，比如「把『所有消息』那条改成连表情包也提醒」
  「加一条：资源区有人发 key 就响」——它自己就把规则改了，不用你去找输入框（见第四节末尾）。

### 三点五点一、让 AI 问清楚再帮你建（向导）

「监听规则」页顶部就是这个向导。**你不需要会写提示词，也不需要一次说清楚**——
说一句大概的，它会反问你几句，把你容易漏的地方补上，确认没疏漏了才生成规则。

比如你只说「有人送用不完的会员套餐，别让我错过」，它会问：

- 要盯哪里？（就那一个帖子 / 这个频道和它下面所有帖子 / 整个服务器）—— 不限范围的话整个服务器都会进来
- 机器人发的算吗？—— 空投、公告这类基本都是机器人发的，最容易漏
- 什么情况**别**烦你？—— 先想清楚不该提醒的，规则才不会变成骚扰

每个问题都带**推荐值**（标了「推荐」的那个）。点一下就算答完，
不想答就留着不点，或者点「按推荐值直接出规则」——没点的它会按推荐值处理，不会卡住你。
最多问 3 轮，够了就出规则。

出规则时它必须交待四件事，你照着看就知道有没有理解错：

| 它给你的 | 你看什么 |
|---|---|
| **它最后理解成这样** | 听哪里 · 听谁 · 听到什么 → 做什么，一行读完 |
| **会提醒你的情况** | 举的例子是不是你想要的 |
| **不会提醒的情况** | ← 重点看这个，漏掉的往往在这里 |
| **怎么验一下** | 照着做一遍就知道到底通不通 |

看着对，点「就这样 → 去填表保存」，规则表单已经填好了，每个字段还能手改；
看着不对，点「不对，我再补一句」，接着跟它说，前面的对话都还在。

写在程序里的领域经验（不用你告诉它）：

- **模糊的需求不能只靠关键词。** 像「有人在无偿送资源」这种，说法有几十种（捐、送、白送、出、转、
  让、有富余、多的、闲置、give away、spare…）。它会用一批关键词做**粗筛**，
  再让模型判「是不是真的在送」，最后用分数阈值卡掉噪音。死关键词漏得多，全交给模型又慢又贵。
- **空投 / 白名单 / 公告类要放开机器人**，否则一条都收不到。
- 抢名额这种时效性强的，冷却时间要短；水群频道用摘要而不是一条条提醒。
- 只盯**一个已有的帖子** → 填那个帖子的 ID；想「这个频道以后新开的帖子都算」→ 填频道 ID + 勾上「同时监听所有子区」。

三条硬规矩，避免生成出「看着对但永远不命中」的规则：

1. **ID 不许编。** 只允许两种来源：本机已经收到过消息的频道/人（自动喂给模型），
   以及你在对话里直接粘的数字 ID。模型编出来的 ID 会被**丢掉**并写进「注意」里，
   提示你手填或先让那个频道来一条消息。
2. **不认识的字段和动作会被清洗掉**，动作不合法时退回「只提醒我」。
3. **生成 ≠ 生效。** 草稿只是把编辑器填好，你改完点「试算」验证、再点「保存规则」才真正启用。

用哪个模型在按钮右边选（默认用「模型接入」里的默认模型）。每一轮问答都是一次模型调用，计入每日上限。
遇到不太会按格式回话的弱模型，它会把模型的原话当成一个问题端给你，不会整个流程卡死——
但这种情况建议换个强一点的模型。

在「AI 工作台」里勾中几条消息后点 **◆ 帮我建条规则**，会带着那条消息跳到这里，
开场白已经替你写好了（「像这条这样的消息就提醒我：…」）。

## 三点八、两种「规则做不到」的需求，各有各的去处

规则只管**以后新来的消息**。下面两件事它管不了，各有专门的入口：

### 1. 「有人开了新帖就告诉我」

论坛频道里发新帖**不是一条消息**，所以光靠监听消息永远等不到。
规则编辑器第一项「**0 · 什么时候触发**」有两个勾：

- 「有人发消息」——默认，频道/子区里的正常聊天
- 「有人开了新帖 / 新子区」——开帖这件事本身

只想要开帖提醒就**只勾第二个**，帖子里后续聊什么都不管。这种规则**不需要写关键词**，
开帖本身就是事件；想按标题筛再加关键词（新帖的「内容」就是帖子标题）。

前提：浏览器旁听只看得见你**开着的页面**，所以那个**论坛频道的帖子列表**得在标签页里开着。
程序靠帖子 ID 里的时间戳判断新旧，所以切换频道时一次刷出来的几十个老帖子不会误报。

### 2. 「把这个帖子里所有人发过的密钥都挑出来」

这是**已经发生过**的消息，规则追不回来。两步：

1. 在 Discord 那个帖子/频道页面，点右下角 dcwatch 药丸 → **「抓历史」**。
   它会自动往上翻页收集，最多 300 条，进度实时显示。
   抓来的消息**只入库，不触发规则、不弹通知** —— 不会突然刷屏几百条提醒。
2. 到侧栏「**批量提取**」页：选那个频道 → 写清要挑什么（说人话，越具体越好）→ 开始。
   会按每批 60 条分几次调模型，结果是一张表，可以**导出 CSV**。

批量提取会核对每条结果**是否真的在原文里逐字出现过**。核不上的标红并写「原文里没找到」——
那是模型自己编的或改写过的，别直接用。这一步是刻意加的：提取类任务模型最容易「补全」一个看起来
很像的值，不核对的话你根本发现不了。

## 四、模型的用武之地（命中后的 6 种动作）

| 动作 | 干什么 | 花不花钱 |
|---|---|---|
| 只提醒我 | 进收信箱 + 浏览器通知 | 不调模型 |
| **AI 判重要度 + 打标签** | 输出 0–100 分、标签、理由、待办；**低于阈值不打扰你** | 每条一次小调用 |
| AI 自动回复 | 带最近 12 条上下文生成回复，直接发回该频道/子区 | 每次一调用 |
| AI 攒够 N 条做摘要 | 不逐条调，攒满 N 条一次总结（水群频道用这个） | 便宜 |
| AI 抽取结构化字段 | 按你的提示词抽成 JSON 存库（价格/单号/地址…） | 每条一次 |
| 转发 Webhook | 原样 POST 给飞书/钉钉/n8n | 不调模型 |

再加一个**手动**入口：「AI 工作台」。在收信箱点消息卡右下的 ✧ 把消息加进上下文，
到工作台问「这几条里哪些今天必须回」「起草一条回复」「抽成表格」，
或用现成快捷键：总结 / 抽待办 / 起草回复 / 翻译。

### v1.8.0：工作台里的模型可以**自己动手改规则**

以前你说「把那条规则改成连表情包也提醒」，它只会回一段「打开监听规则页 → 找到第 5 项 → 勾掉
→ 保存」。你来问它，本来就是因为不想一格一格找。现在它自己就能做完：

```
你：把「所有消息」那条改成连表情包也提醒
它：✔ 看了一遍你的规则
    ✔ 改了规则「所有消息」的：min_len
    改好了。这条现在不看字数了，纯图片和表情包也会提醒你。
```

它能做的事：**列出规则 / 新建 / 修改 / 启用停用 / 删除 / 拿假消息试算 / 查真实频道 ID /
搜已经收到的消息 / 看现在的收信状况**。几条纪律是写死在程序里的：

- 改之前一定先把你的规则列出来，**不许凭名字猜 id**，也不许自己编频道 ID（编了会被程序洗掉）；
- 改完会试算一次，然后用一句话告诉你「改了什么、现在会不会命中」；
- **删除不可逆**，你没明确说「删」它只会停用；
- 每一步动作都会显示在回答上面（`✔` 是真改了配置，`·` 只是读了一下），你能核对它到底动了什么。

改动**立刻生效**，「监听规则」页会当场刷新。不放心的话，去「模型接入」页把
**「允许模型直接改规则」**关掉 —— 关掉之后它退回只讲步骤的老样子，两条动手的路都封死。
同一页还有**「边想边显示（流式）」**：模型想十几秒才开口是常事，开着流式你能看见它一个字一个字往外吐，
而不是盯着一个「…」猜它是不是卡死了。接口不支持函数调用的模型（一些便宜的国产模型、本机 Ollama）
会自动退回文本指令模式，能力一样，界面上会写一行「改用文本指令模式」。

工作台里的模型**知道自己在这个程序里**：程序每次都会先告诉它这台机器的实况 ——
版本、收信方式是浏览器旁听还是 Token、现在有没有浏览器在盯、你有哪些规则、
最近哪些频道来过消息。所以你可以直接问「我为什么收不到消息」「这条规则为什么没命中」。

**直接贴频道链接就行**，不用自己去找 ID：

```
帮我监听 https://discord.com/channels/1134557553011998840/1513056466293096518
```

程序会把链接拆成服务器 ID 和频道 ID 一起交给模型，输入框上方还会冒出一条
「用这个频道建规则」，点了就带着这个频道 ID 跳到向导。它不会再回你
「我无法访问第三方平台，建议你写个 Discord 机器人」—— 监听是**这个程序**在做，不是模型在做。
同理，在这里说「帮我写规则」指的一定是**监听规则**，不会被理解成群规。

省钱三件套：规则先用**关键词/作者**把范围收窄 → 再让模型判分 → 冷却 + 每小时上限 + 每日总上限（设置页）。

## 五、收信开关在哪

左下角两个开关：**浏览器旁听**（关掉后扩展转来的消息一律丢弃）、**Discord Token**（关掉即断开 Gateway）；
下面「全部暂停」是总闸，一键全关/全开。Telegram / 邮件位子已经留好
（`sources` 字段 + 同一套规则引擎；任何外部来源只要 POST 到 `/api/ingest` 就能接进来，
格式见 `extension/content.js` 里发的那个 JSON）。

## 六、命中之后怎么提醒你 / 往哪儿转（界面「通知与转发」页）

### 本机提醒（Win11）

| 开关 | 实际做什么 | 依赖 |
|---|---|---|
| Windows 系统通知 | 右下角弹原生 toast（通知中心里也能翻） | 无。调 PowerShell 的 WinRT 接口，不装库 |
| 提示音 | 默认系统「叮」；也可指定一个 `.wav` 绝对路径 | 无。Python 自带 `winsound` |
| 网页通知 | 浏览器通知，要开着界面标签页 | 首次会问你要权限 |
| 免打扰 `23:00 → 08:00` | 这段时间**只静音本机**，转发照发 | — |

系统通知有 4 秒防刷屏（同一波消息只弹一条），刷屏频道不会把你炸穿。

### 转发出口：一条出口 = 一个 HTTP 请求

程序里没写死任何第三方服务。加一条出口就三步：

1. 点「＋ 添加出口」，旁边下拉里挑个**预设**（已内置企业微信 / Server酱 / 飞书 / 钉钉 / Telegram /
   Discord 频道 / 纯文本 / 表单 / GET / 整条 JSON）。预设会把请求方式、请求体模板、连地址格式都填好。
2. 把地址里那段中文（`把你的SendKey填在这里` 之类）换成你自己的 key。地址框默认打码，点 👁 看明文。
3. 点「测试」。通了就标 ✓，左下角状态灯里会亮它。**没测通也照样会转发**，只是状态灯里不列。

请求体里能用这些占位符，发送前替换成真值：

`{{text}}` 整条（标题+正文）· `{{title}}` 标题 · `{{body}}` 正文 · `{{content}}` 原始消息文字 ·
`{{author}}` `{{channel}}` `{{server}}` · `{{url}}` 跳回 Discord 的链接 ·
`{{score}}` `{{tags}}` `{{todo}}` AI 结果 · `{{json}}` 整条消息的原始 JSON（不转义，直接嵌进结构里）

JSON 模板里的占位符会按 JSON 字符串正确转义，消息里带引号和换行也不会把请求体搞坏。
请求头也能填（一行一个 `名字: 值`，比如 `Authorization: Bearer xxx`），头里也能用占位符。

各家的地址去哪儿拿：

| 出口 | 怎么拿 | 风险 |
|---|---|---|
| **Discord 频道 Webhook** ← 推荐 | 你**自己**建个服务器（免费）→ 频道 → 设置 → 整合 → 创建 Webhook → 复制链接 | 零。官方功能，不用 bot、不用 token，手机 Discord 直接收推送 |
| **企业微信群机器人** | 群 → 设置 → 群机器人 → 添加 → 复制 Webhook | 零。也能把微信用户拉进群看 |
| **微信：Server酱** | sct.ftqq.com 微信扫码 → 拿 SendKey | 零。推到微信「服务号」，官方通道 |
| **飞书 / 钉钉** | 群 → 设置 → 群机器人 → 添加 → 复制 Webhook | 零 |
| **Telegram** | @BotFather 建 bot 拿 token；给 bot 发条消息，再找 @userinfobot 要 chat_id | 零 |
| **自建 / n8n / 任何接口** | 挑「通用 JSON」或「整条消息」预设，填你自己的地址 | 零 |

从老版本升上来的配置会自动搬过去：原来填在固定框里的 Discord Webhook、Telegram、Server酱、
企业微信、自定义 Webhook 都会变成对应的出口，不用重填。

**关于直推个人微信**：要用 itchat / wechaty 那类非官方网页协议顶着你的登录态模拟客户端，**封号风险高**，
微信这几年封得很严，所以这里没做。想让消息落到微信上，就走 Server酱 或企业微信机器人，效果一样、风险为零。

「分数低于多少不往外发」配合规则里的 **AI 判重要度**：让模型打 0–100 分，只有 ≥ 阈值的才往手机上推，
低分的静静躺在收信箱里。这是不被刷屏的关键。

## 七、数据与隐私

Token、API Key、Webhook 地址、消息全在本机数据库；界面读取时一律只回显掩码（`***后四位`），
保存时掩码不会把真值冲掉。默认只监听 `127.0.0.1`，要在别的机器看就 `--host 0.0.0.0`（自己加反代和鉴权）。
消息按「保留天数」自动清理（默认 14 天）。

数据库位置：源码运行 = 程序目录下的 `dcwatch.db`；exe 运行 = `%LOCALAPPDATA%\dcwatch\dcwatch.db`
（exe 每次启动会把自己解包到临时目录，数据不能放那里，会被清掉）。

**不用记这两条路径** —— 打开界面「设置」页，第一张卡片「我在跑的是哪一份」直接写着你这台机器上
代码在哪、配置和密钥在哪。左上角和右上角的版本按钮点开也有。

### 「我换了个文件夹跑，怎么带着上次配的模型和密钥？是不是泄露到 GitHub 了？」

没有泄露。这两件事分开看：

| | 会不会跟着走 |
|---|---|
| 代码（server.py / ui.html / 扩展） | 你从 GitHub 拉的就是代码，**里面没有任何配置** |
| 配置（模型、API Key、规则、消息） | 只在 `dcwatch.db` 里，**从不上传、从不进仓库** |

仓库里 `.gitignore` 明确排除了 `*.db`，所以数据库文件不可能被提交。你拉下来的 zip 里也不会有它。

那为什么新文件夹会「记得」旧配置？看你用哪种方式启动：

- **跑 exe**：配置在 `%LOCALAPPDATA%\dcwatch\dcwatch.db`，这是**全机共享**的一份。
  不管你把 exe 放在哪个文件夹、解压几次，读到的都是同一份配置 —— 所以它当然还记得你的模型和密钥。
  这是设计如此（不然每次更新 exe 都得重新配一遍）。
- **双击 `启动.bat` 跑源码**：配置就在 `server.py` 旁边。换一个新文件夹跑 = 一份全新的空配置。
  如果新文件夹里也有旧配置，只有两种可能：你把新文件**覆盖进了旧文件夹**，或者你其实在跑 exe。

想彻底重来：关掉程序 → 把 `dcwatch.db` **改名**（别删，万一想找回规则）→ 再启动就是干净的。


界面里另有三处：左上角 dcwatch 旁边的小按钮、右上角同样一个（任何页面都看得到）、「设置」页第一张卡片。
点任何一个会展开抽屉，把**程序版本**和**扩展版本**分开列清楚（这是两个东西，各自升级）。
导出的诊断包第一段也有全部这些信息。

### 界面上的版本和你以为的不一样？

**十次有九次是：你启动的是另一个文件夹里的程序。** 新文件解压到了新位置，
但你双击的还是旧位置的「启动.bat」或旧的桌面快捷方式。扩展是 Chrome 单独从文件夹读的，
所以会出现「**扩展是新的，界面是旧的**」这种拧着的情况。

`/version` 页上「代码在哪」那一行就是真相。去那个文件夹，把新版文件覆盖进去，
或者直接到新文件夹里双击启动.bat。跑 exe 的话，重新打包前的 exe 永远是旧版本。

Chrome 的 `chrome://extensions` 卡片上写的是扩展自己的版本，和程序版本不必相同，
但不能低于 `/version` 上写的「浏览器扩展至少要」。

## 八、打包成 exe（Windows）

在 Windows 上（不能在 Linux/云端交叉编译，PyInstaller 只能打当前系统的包）：

```
双击 build.bat
```

> **先看这段，别到时候以为死机了。** 打包是这套东西里**唯一**重的一步：要下载安装
> PyInstaller、扫一遍全部依赖、再生成一个十几 MB 的 exe，全程几百 MB 内存和大量磁盘读写，
> 而且 Windows Defender 会实时扫这个刚生成的、没签名的 exe。慢的电脑要**十几分钟**，
> 中间长时间一行输出都没有是正常的。
>
> **千万别因为「没反应」再双击一次。** 两个 PyInstaller 同时跑会把内存吃光，Windows 一开始
> 疯狂读写页面文件，整台机器会卡到鼠标都不动 —— 一小时都缓不过来是可能的。
> 现在 `build.bat` 会自己挡住第二次运行（靠 `%TEMP%\dcwatch_build.lock`），
> 但还是别去试。**打包这一步跟监听程序本身无关，只在你要 exe 的时候才需要跑一次。**

它做三件事：装 `aiohttp` + `pyinstaller` → `python -m PyInstaller --clean --noconfirm dcwatch.spec` →
把 `extension/` 一起拷到 `dist\`。产物：

```
dist\dcwatch.exe        约 15–20 MB，双击即跑，会自动打开 http://127.0.0.1:8777
dist\extension\         浏览器旁听要装的扩展（exe 内部也带了一份，界面上能直接下载）
```

- 需要机器上先有 Python 3.10+（只是**打包**要，打完的 exe 在别的没装 Python 的电脑上也能跑）
- **怎么停**：双击 `停止.bat`（它先请程序自己退，退不了就强制结束）。关掉黑窗口也一样是停。
  再不行就任务管理器（Ctrl+Shift+Esc）找 `python.exe` / `dcwatch.exe` 结束任务
- **双击第二次不会开出第二个程序**：端口已被占用时它不再启动，只把已经在跑的那个界面打开
- 那个黑窗口 = 程序本体，关掉就等于停止监听，最小化即可。想彻底没窗口：把 `dcwatch.spec` 里
  `console=True` 改成 `False`（代价是看不到日志，只能从界面的「运行日志」看）
- 开机自启：直接在界面「设置 → 开机自启动」打开开关就行（写当前用户的注册表 Run 键，不需要管理员）。
  打包成 exe 后这条自启项会自动指向 exe 本身。**想取消**：把那个开关关掉，或者
  任务管理器（Ctrl+Shift+Esc）→ **启动应用** → 找到 dcwatch → 禁用。
  默认是关的 —— 你没开过它就不会自己启动
- 端口被占了会提示换端口：`dcwatch.exe --port 8778`（扩展里的 ENDPOINT 也要跟着改）
- 杀软误报是 PyInstaller 的通病（未签名的打包 exe）。介意就别打包，直接 `python server.py`

## 八点五、出问题了：导一份诊断，别让人猜

「运行日志」页最上面有 **⬇ 导出诊断包（.txt）**。一个文件说清全部情况：

| 段 | 里面是什么 | 能看出什么 |
|---|---|---|
| **[0] 一眼结论** | 程序自己把常见原因查一遍，每条写清**现象 + 该做什么** | 大多数情况看完这一段就够了 |
| [1] 程序 | 版本、是不是 exe、Python、数据库大小、跑了多久、库里多少条 | 版本对不对、数据有没有在进 |
| [2] 出网设置 | 代理、端点、Key 有没有填、24 小时调了几次、**最近 5 条报错** | 模型拉不到、转发失败 |
| [3] 收信来源 | 每个浏览器桥：账号、浏览器、扩展版本、活没活、在盯哪个频道，以及**扩展那边解析了几条 / 上报了几条 / 因为什么跳过 / 最近 6 条的判定** | 「消息没收到」到底断在哪一环 |
| [4] 规则 | 每条规则的全部条件 + 命中次数 | 规则为什么不命中 |
| [5] 通知与转发 | 提醒开关、免打扰、每个出口（**只留域名**） | 为什么不响、为什么没转出去 |
| [6] 日志 | 最近 200 条 | 每次模型调用、每次转发、每个错误原文 |
| [7] 消息 | 最近 30 条的元数据 + 正文前 40 字 | 消息进来时长什么样 |

**里面没有 Token、没有 API Key，出口地址只保留域名。** 不想带消息正文就把旁边的勾去掉。
想先看看再决定发不发，点「先看看里面有什么」，能直接在界面里读，也能一键复制。

「消息没收到」这类问题，有了 [3] 段就不用猜了：
扩展解析到 0 条 = 没认出页面；解析到但没上报 = 看跳过原因；上报了但收信箱没有 = 程序侧的问题。

**v1.7.2 起这些判断程序自己会做一遍**，写在最前面的 [0] 段，也直接显示在界面「收信箱」的顶部 ——
一条规则都没建、某个 Discord 标签页需要按 F5、解析到了却一条都没上报、有消息但一条都不命中，
这些都会被指名说出来，并附上该点哪里。所以先看 [0]，看不懂再往下翻原始数据。

**v1.7.3 又加了一段 [4.5]「拿真实消息试算」**，因为「规则填了什么」和「会不会命中」是两回事：
频道 ID 填进了「子区」那一栏、第 0 项勾成了只听新帖、忘了勾私信 —— 光看条件本身，
每一条都很像是对的。所以程序直接拿你真实见过的消息（库里的；库是空的就用扩展看到的正文）
对每一条规则跑一遍，逐条印出**卡在哪个输入框**：

```
[4.5] 拿真实消息试算
  消息： 有人送 mimo 的 key （来源：库里的消息）
     [停] 频道监听-所有消息 → 会命中（这条是停用的，就算命中也不会提醒）
     [开] 帖子监听-所有消息 → 不命中 · 触发类型对不上：这条规则只在「开新帖」时触发，普通聊天消息永远不算
```

同一版起，[4] 段每条规则前面会印出「什么时候触发」，只听新帖的那条会被直接标出来。

### 想看看 AI 是被怎么指挥的？

「监听规则」页标题右边有个不打眼的 **内部提示词** 按钮。向导那段几千字的提示词原样摊给你看，
包括「它什么时候用这段」「为什么这么写」，可以整段复制走。

这两条（规则向导、一句话生成）写死在程序里不给改 —— 改坏了向导会直接失效。
**命中之后那几种动作的提示词是可以改的**（打分、摘要、抽取、自动回复），在「模型接入」页最下面。

## 九、故障对照

| 现象 | 原因 |
|---|---|
| **整台电脑卡住 / 长时间无响应** | **几乎不会是监听程序**：它是一个 Python 进程，常驻内存 40–60 MB，所有后台循环都有间隔，通知最多 4 秒一条。先想想是不是双击了 `build.bat`（打包那步很重，见第八节），或者同时在跑别的东西。要查证据：Win 键搜「**可靠性监视器**」，它按时间列出哪个程序挂起过 |
| 点了启动没反应 / 界面打不开，说端口被占 | v1.6.3 起 `启动.bat` 会自己清掉上次没退干净的进程再启动。手动来一次就是双击 `停止.bat`（它会把端口释放掉）。要是提示占端口的是**别的程序**，那就换端口：`启动.bat 8778` |
| 我怕它还在后台跑 | 双击 `停止.bat`。它没有服务、没有守护进程，杀掉就没了。唯一会自己回来的是你在设置里开过「开机自启动」——任务管理器 → **启动应用** → dcwatch → 禁用 |
| 工作台的模型说「我无法访问 Discord」，还劝我去写机器人 / 用 Zapier | 你跑的是 v1.6.1 或更早：那时工作台的系统提示词只有一句话，模型不知道自己在一个监听程序里。升到 v1.6.2 以上 |
| 工作台把「帮我写规则」听成群规、游戏规则 | 同上，v1.6.2 起「规则」在工作台里被明确定义为监听规则 |
| 不知道自己装的是哪一版 | 打开 <http://127.0.0.1:8777/version>，一页说清（这一页不用界面也不用 JS，缓存骗不了它）。界面上另有三处：左上角、右上角、「设置」页第一张卡片 |
| **扩展是新版，但界面上找不到版本号 / 界面还是老样子** | 你启动的是**另一个文件夹**里的旧 `server.py`。扩展是 Chrome 单独从文件夹读的，所以两边会拧着。打开 `/version` 看「**代码在哪**」那一行 —— 那就是你真正跑起来的那份。是 404 就说明连 `/version` 都还没有，即 v1.7.1 之前的旧版 |
| 覆盖了新文件，界面还是旧的 | v1.7.1 起 `ui.html` 带 `no-store`，不会再被浏览器缓存。旧版遇到这种情况按 **Ctrl+F5** 强刷 |
| 换了新文件夹跑，却带着上次配的模型和密钥；怀疑密钥进了 GitHub | **没有泄露**。代码和配置是两回事：仓库里只有代码，`.gitignore` 排除了 `*.db`。配置只在 `dcwatch.db` 里，而 **exe 模式下这个文件是全机共享的**，所以换文件夹也是同一份。详见第七节，界面「设置」页第一张卡片直接写着你这台机器上它在哪 |
| 「有人开新帖就提醒我」没反应 | 规则第 0 项「什么时候触发」要勾上「有人开了新帖 / 新子区」（默认只勾了消息）；并且那个**论坛频道的帖子列表**得在浏览器标签页里开着 |
| 想找帖子里以前发过的东西，规则怎么都抓不到 | 规则只管以后新来的消息。已经过去的要：页面右下角药丸 → **抓历史**，再去「批量提取」页。见第三点八节 |
| 批量提取的结果标红说「原文里没找到」 | 那条是模型改写或编的，别用。这是故意标出来的，不标你发现不了。可以把「要提取什么」写得更具体再来一次 |
| 诊断包里写「解析 N 条 → 上报 0 条，整批渲染 N」 | 你跑的是 **v1.7.1 或更早**的扩展：那时候「一批冒出 8 条以上」一律当成 Discord 在渲染历史而整批丢掉，于是**开奖、发码那种一下刷屏十几条的时刻反而全漏**。v1.7.2 改成看消息自己的时间戳（只有整批都是旧消息才算渲染回填），升级扩展即可 |
| 界面显示两个桥，其中一个「浏览器」认不出来 | 那是**页面里的旧脚本在直连**：扩展重载/更新过，而那个 Discord 标签页没按 F5。它还能转发，所以看着像在工作，其实扩展的改动一点没生效。到那个标签页按 F5，右下角药丸也会直接提示这件事 |
| 装好了、灯也绿，但从来没提醒过我 | 先看界面「收信箱」顶部的结论条。最常见的就是**一条规则都没建**（收信 ≠ 提醒，规则才决定提醒什么）；其次是规则条件太窄。v1.7.3 起导出诊断包看 **[4.5] 段**，它拿真消息把每条规则跑一遍，直接告诉你卡在哪个输入框 |
| 规则明明填好了、也开着，就是不响 | 十有八九是这两个：①第 0 项「什么时候触发」只勾了「有人开了新帖」，那么频道里聊翻天也不会响；②频道 ID 填进了「子区」那一栏（或反过来）。两个都在 [4.5] 段里会被直接点出来。最快的自测：**自己在那个频道发一条消息**，看收信箱有没有立刻出现 |
| Discord 一直开着，界面却时不时写「失联」；或者后台标签页里的消息迟到一分钟 | Chrome 会给**隐藏标签页**里的定时器降频（藏久了变成每分钟才跑一次），而服务端 90 秒收不到心跳就判失联。v1.7.4 修了两处：消息不再等合批定时器，第一条立刻发；后台脚本用 `chrome.alarms` 每 30 秒主动去标签页拉一次心跳（这个不受可见性影响）。**要升级扩展到 v1.7.4** |
| 别人发的**表情包 / 图片 / 贴纸**从来收不到 | v1.7.x 及更早一律按「没有文字」丢掉。v1.8.0 起会翻译成 `[图片]`、`[贴纸 xx]`、`:emoji:` 上报（**扩展要升到 v1.8.0**）。另外那条规则不能有关键词/正则（纯表情没有文字，永远匹配不上），「最短字数」要是 0 |
| 让 AI 帮我改规则，它只回一串「你去点第几个勾」 | v1.8.0 起它自己就能改。检查：①程序和界面都是 v1.8.0（看左上角版本药丸）；②「模型接入」页的**「允许模型直接改规则」**是勾上的 |
| 工作台点了发送，界面上就一个「…」不动 | 模型在想。开着「边想边显示（流式）」就能看到它一个字一个字吐；真调不通会直接显示报错状态码，不会无限等 |
| 收信箱里没有「回复」输入框了 | 这是对的：**浏览器旁听模式发不出消息**，v1.8.0 起干脆不画那个框（以前填完一段话再吃一个报错）。要在 dcwatch 里直接回复，得去设置页换成 Bot Token 模式 |
| 规则调好了想搬到另一台电脑，或者想把一份规则发给朋友 | v1.9.0 起「监听规则」页有 **⇡ 导出规则 / ⇣ 导入规则**。导出的 json 里只有规则，不含 Token 和 API Key；导入前有一页预览，告诉你哪几条会被覆盖、覆盖掉什么，点确认才写 |
| 导入规则以后那条规则一条都不命中 | 看预览里有没有 ⚠：①动作是 `ai_*` 但你还没在「模型接入」配模型；②文件里的「最短字数」比你要收的消息还长；③规则导入后是**停用**状态（预览里会写「导入后是停用状态」），到列表里把开关打开 |
| 连上了但 `content` 全空 | 没开 MESSAGE CONTENT INTENT |
| 某频道一条都收不到 | bot 没有那个频道的 View Channel 权限 |
| 日志 `4004` | Token 错或已被 Reset |
| 日志 `4014` | Intent 没在开发者后台勾选 |
| AI 自动回复没发出去 | 缺 Send Messages / Send Messages in Threads 权限 |
| 拉模型转半天然后失败 | 网络到不了对方。设置页填代理；国内直连 api.openai.com 基本不通。错误提示里会写清是超时 / 401 / 404 |
| 拉到的模型看着像模像样但一调用就报错 | 检查下拉里有没有「（演示）」前缀。有＝你其实没连上本机程序，那是演示数据 |
| 界面右上角显示「演示模式（未连上后端）」 | 前端没连到后端（server.py 没起 / 端口不对），此时看到的是示例数据，改任何设置都不会落盘 |
| 改完设置提示「没保存成功」 | 后端把请求拒了，提示里带真实状态码，照它说的改；以前这里会假装保存成功 |
| 扩展装了但收信箱顶部说「还没有任何浏览器在旁听」 | 九成是装完扩展没在 Discord 页面按 F5。其次是 dcwatch 没启动、端口不对（弹窗里改） |
| 收信箱顶部说「最近 90 秒没有心跳」 | Discord 标签页关了/睡了，或扩展被停用。打开频道页按 F5 |
| 顶部说「有浏览器还在跑旧版扩展」 | 覆盖文件后没刷新扩展：`chrome://extensions` 点刷新箭头 ⟳，再回 Discord 按 F5 |
| 改了扩展代码但毫无变化 | 同上，必须刷新扩展 + F5。看扩展卡片上的版本号确认到底更没更 |
| 两个浏览器都开着同一频道，会不会收到两遍 | 不会。按消息 ID 去重，只入库一条、规则只跑一次、AI 只调一次 |
| 扩展在线但一条都不进来 | 消息得是**你打开着的那个频道**的新消息；刚切频道的历史消息故意不上报；纯图片无文字会跳过 |
| 浏览器旁听收到的作者 ID 是空 | 那人用的是默认头像（URL 里没有用户 ID）——用「昵称包含」来匹配，或让他的头像消息先出现一次 |
| 私信收到了但一条规则都不命中 | 规则**默认不听私信**。去「听哪里」勾上「包含私信 DM」；不勾的话试算会显示被 `dm-off` 挡下 |
| 个人 Token 模式连不上（4004） | token 复制错了，或账号开了两步验证后 token 已轮换；这条路本身也可能随 Discord 客户端版本变化而失效 |
| 点「测试」显示系统通知 ok 但没看见 | 检查 Windows 设置 → 系统 → 通知，别开着「专注助手/免打扰」；通知会归到 PowerShell 名下 |
| Telegram 报 401 | token 错；报 400 chat not found = chat_id 错，或你还没先给 bot 发过消息 |
| Server酱 报 code≠0 | SendKey 过期/写错，或当天免费额度用完了 |
| 转发没动静，日志也没报错 | 那条消息没命中任何规则（规则页「试算」验一下），或分数低于「不往外发」阈值 |
| exe 打包失败 | 报错发我。常见是 pip 装不上（换源）或杀软拦了 PyInstaller 写文件 |

## 十一、换个账号 / 换个 AI 接手

这个项目是在 cloud.browser-use.com 上由 AI 断续做出来的。**AI 的记忆不跟着账号走，跟着这个仓库走。**
所以只要仓库在，换号、换工具（Claude Code / Cursor）、甚至换到你自己电脑上，都能接着做。

**两条路**

| | 怎么做 | 代价 |
|---|---|---|
| A · 只是换设备/换人 | 把新号邀请进同一个 project（设置 → Project），开会话时选**同一个工作区** | 文件、记忆、历史会话全在，无缝。但额度是按 project 算的，换号不给新额度 |
| B · 就是要换 project 拿新额度 | 新号是新工作区，我这边的记忆一个字都过不去 —— **让新的 AI 从这个仓库接手** | 要它自己 clone、读三份文件；聊天记录不过去，但项目状态全在 |

**走 B 的话，新会话第一句话复制这段：**

```text
接手一个已有项目：https://github.com/tqzbceb/claude
先 clone 下来，按顺序读根目录的 AGENTS.md、HANDOFF.md、CLAUDE.md 三份文件，
然后按 HANDOFF.md 里「未完成」的第一项继续做，不要重新规划已经做完的东西。
回归套件在 tests/，改代码前后都要跑：cd tests && ./runall.sh e2e.py e2e_ai.py
交付包按 AGENTS.md「怎么出交付包」那节打（26 个文件，不含 tests/ 和这三份交接文件）。
做完更新 HANDOFF.md，我给你 GitHub token 你推回 main。
```

**你要自己带过去的三样东西**（仓库里故意没有）

1. **一个新的 GitHub PAT** —— 凭据不进仓库。新 AI 要推代码时你现给一个，用完在 GitHub 上 revoke。
2. **一份诊断包** —— 程序界面「运行日志」页 → 导出诊断。新接手的 AI 只能靠这个知道你机器上的实况
   （跑的是哪一版、扩展活没活、规则会不会命中）。
3. **你手上程序的版本号** —— 打开 `http://127.0.0.1:8777/version` 那页，截图或念给它。

**别让新 AI 拿你手上那个 zip**：zip 是给你运行的，里面故意不含 `tests/` 和交接文件。让它从 GitHub clone。
